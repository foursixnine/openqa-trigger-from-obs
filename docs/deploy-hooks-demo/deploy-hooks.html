Deploy hooks: what happens after git pull

After every git pull of the checkout, the git post-merge hook script/deploy-hook.sh runs script/deploy_on_pull.py (create and regenerate project folders) and script/cleanup_on_deploy.py (remove folders that no XML wants any more). Generated by docs/deploy-hooks-demo/hooks_demo.py from commit e4d3408 docs: add a page showing what the deploy hooks do on 2026-10-15: it runs the real scripts against scratch clones; nothing talks to OBS.

Project folders per XML

An XML with <projects_enabled range="X..Y" project="V,W"/> lists its folders: each value replaces the one character class of project_pattern. They are created whenever the XML changes, and removed when a change drops them. Without the element, the folder is the literal project_pattern, or the matching t/obs/<Project> folders, created when the XML is added. Deleting or archiving an XML removes its folders, even hand-edited ones.
